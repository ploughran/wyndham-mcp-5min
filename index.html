The Business Case
Franchise Leads Captured Where Salesforce Isn't
Wyndham's franchise team lives in Salesforce — but prospective owners don't. This agent meets them in Google Chat, a website widget, or any surface, and creates a fully enriched Salesforce lead in real time without any manual entry.
How It Works
1
2-question qualification — Name + email, then one intent question. Budget signals inferred from natural language — no form.
2
Google Agentspace scores the lead — BANT scoring, tier assignment (Hot / Warm / Cold), routing decision — before calling Salesforce.
3
Salesforce MCP creates the Lead record — name, email, intent, budget, score, routing tier — written directly via MCP. No webhook, no middleware.
4
AE notified instantly — hot leads route to Senior AE within minutes. Full context already in Salesforce.

The Tough Questions — and How We Answered

Real objections from the CIO and CMO, live from the room. Not hostile — the right questions from technical buyers doing their job.

CIO
"Is this actually live? Or is this scripted?"
Response
Yes — live, real API calls, real data. We showed MuleSoft gateway logs mid-demo with timestamps matching the agent's conversation turns.
CIO
"What happens when a new model comes out? Does this all break?"
Response
MCP is model-agnostic. Swap the model, the integrations stay. We treat model upgrades like deployments — agent test suites run before any version hits production.
CIO
"Who controls what data the agent can see?"
Response
Salesforce Named Principal + OAuth resolves this at the identity layer. Every MCP tool call inherits the authenticated user's entitlements — the agent can only see what that user is allowed to see. MuleSoft enforces it at the gateway. No custom auth logic, no workarounds. Same security model as any governed API. MuleSoft can also extend this to external MCP Servers — one identity fabric across your entire tool ecosystem.
CMO / CIO
"No one knows what these models will cost. How do I budget for this?"
Response
AELA converts unpredictable per-token costs into a governed per-conversation rate you can forecast. That's the CIO's best friend.
CIO
"We're worried about runaway consumption. What's the cost gateway?"
Response
MuleSoft Omni Gateway + Policies pull this entire picture together. Rate limits, quotas, and SLA policies are applied at the MCP bridge layer — before any tool call hits a backend system. Every agent invocation is telemetered per team, per use case, per model. Visibility before it hits your bill, not after. This isn't theoretical — the MCP bridge is the enforcement point, and Policies are the dial you turn.
CIO
"Are we paying Opus prices for tasks Sonnet could handle?"
Response
Model tiering is a first-class cost strategy. Sonnet handles 80%+ of support volume. Opus earns its cost only for complex reasoning — multi-system structuring, escalations, agentic planning.
